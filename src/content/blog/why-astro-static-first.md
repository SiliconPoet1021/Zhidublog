做个人博客时，很容易先陷入技术选型：要不要数据库？要不要做后台？评论系统怎么接？但这些问题应该从真实需求出发，而不是从“以后可能会用到”出发。

## 先确定第一版需求

这个站点第一版只需要解决四件事：

1. 能稳定发布 Markdown 文章。
2. 有清晰的分类、标签和文章详情页。
3. 有良好的 SEO、RSS 和移动端阅读体验。
4. 部署简单，维护成本低。

没有用户注册，也不需要在线编辑器。这意味着内容可以在构建时全部生成，没有必要先运行一个长期在线的内容服务。

## 为什么选 Astro

Astro 很适合以内容为中心的站点：

- 默认输出静态 HTML，首屏加载快。
- Markdown 和 MDX 的内容工作流足够直接。
- 可以按需加入交互组件，而不是默认加载整个应用框架。
- 对 SEO、RSS 和站点地图的支持比较自然。

对于一个以文字为主的博客，这些能力比“页面里能不能放复杂应用”更重要。

## 为什么不先上数据库

第一版文章数量有限，内容结构稳定。如果把文章放进数据库，就需要额外处理：

- 数据库连接和备份；
- 内容管理后台；
- 登录与权限；
- 服务端运行和监控。

这些工作不会直接提升写作体验，却会显著增加维护成本。

等真正出现多人写作、在线编辑或复杂互动需求时，再引入后端也不迟。

## 部署与访问统计

构建命令保持简单：

```bash
npm run build
```

构建结果在 `dist` 目录，可以发布到 Cloudflare Pages，也可以部署到自己的静态服务器。访问统计只在页面加载一个轻量脚本，不参与内容生成。

```text
写 Markdown
  → Astro 构建静态页面
  → Cloudflare Pages 发布
  → 百度统计查看访问趋势
```

## 接受第一版的不完整

第一版的目标不是“功能齐全”，而是“可以开始写”。

评论、搜索、在线编辑和自建统计看板都可以后续再补。真正应该优先验证的是：这个站点的内容结构是否适合我持续表达。

技术选型没有绝对正确。能在当前阶段降低阻力，并给未来保留升级空间，就是合适的选择。
