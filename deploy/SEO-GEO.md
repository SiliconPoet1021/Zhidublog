# 知渡博客 SEO 与 GEO 实操清单

SEO 是让页面在传统搜索结果中被发现、理解并点击；GEO 是让内容更容易被 ChatGPT、Perplexity、Google AI 摘要等生成式搜索识别、引用和链接。GEO 不是另一套神秘设置，它建立在技术可抓取、作者身份清楚、内容可验证和表达可引用之上。

## 当前基础

项目已经具备：

- XML 站点地图、RSS、`robots.txt`
- 每页唯一的标题、摘要和 canonical 地址
- Open Graph、Twitter Card 和中文页面语言声明
- 首页 `WebSite`、关于页 `ProfilePage`、文章页 `BlogPosting` 和面包屑结构化数据
- 作者统一为 `JinSun`，并连接 GitHub 与关于页
- 文章分类、标签、相关阅读、更新时间和内部链接
- 百度、Google、Bing 站点验证入口与访问统计可选配置

## 第一优先级：先做站外配置

### 1. 绑定正式域名

长期使用 `*.pages.dev` 也可以访问，但正式域名更利于品牌记忆、搜索归因和外部引用。绑定后必须把 Cloudflare Pages 的 `SITE_URL` 改成正式地址并重新部署。

例如：

```env
SITE_URL=https://blog.example.com
```

不要在搜索引擎已经收录后再频繁更换域名。确实需要更换时，应使用 301 跳转并更新 Google Search Console 中的地址变更。

### 2. 提交搜索平台

至少在以下平台创建站点并验证所有权：

1. Google Search Console：提交 `https://你的域名/sitemap-index.xml`
2. Bing Webmaster Tools：提交同一份站点地图
3. 百度搜索资源平台：提交同一份站点地图，适合中文受众

Google 和 Bing 验证后，把验证值填入 Cloudflare Pages 环境变量：

```env
PUBLIC_GOOGLE_SITE_VERIFICATION=
PUBLIC_BING_SITE_VERIFICATION=
PUBLIC_BAIDU_SITE_VERIFICATION=
```

重新部署后，在页面源代码中确认对应的 `<meta>` 验证标签已经出现。

### 3. 检查抓取状态

- 在 Google Search Console 对首页和一篇重要文章使用“网址检查”
- 在 Bing Webmaster Tools 查看抓取和索引状态
- 在百度搜索资源平台查看抓取诊断、索引量和站点地图状态
- 确认 `/robots.txt` 返回 `200`，并允许正常搜索引擎访问
- 确认 `/sitemap-index.xml` 使用的是正式域名

搜索引擎收录需要时间，不应因为一两天没有结果就重复改标题或批量提交。

## 第二优先级：持续优化内容

技术框架只解决“能被理解”，排名和引用主要取决于内容是否解决真实问题。

### 推荐结构

每篇文章尽量包含：

1. 一个具体问题，而不是宽泛主题
2. 开头直接给出结论、适用条件或最终结果
3. 背景、限制、方案比较和失败路径
4. 可运行的代码、真实报错、截图或数据
5. 明确的步骤、检查表或判断标准
6. 一手来源、版本号和日期
7. 与其他相关文章的链接
8. 内容确有变化时更新 `updatedDate`

标题应准确回答“解决什么问题”，避免为了关键词写成与实际内容不符的标题。摘要要独立可读，因为它可能直接出现在搜索结果、RSS 或 AI 答案中。

### 建立主题集群

围绕一个方向持续写多篇互相链接的文章，比零散热点更容易建立专业身份。例如：

- Astro 静态博客搭建、部署、公式、搜索、性能
- Cloudflare Pages 与自定义域名、统计、安全
- 国内访问、备案、CDN 与搜索收录
- 个人知识管理与长期写作

文章之间的链接应自然说明“为什么相关”，不要为了链接而堆砌。

## GEO：让答案更容易被正确引用

生成式搜索更偏好清楚、可追溯、可验证的内容。重点不是“写给 AI 看”，而是让读者和机器都能快速判断：

- 谁写的
- 什么时候写的或更新的
- 基于什么经历或来源
- 结论适用于什么条件

建议每篇长文都做到：

- 标题直接对应一个明确问题
- 开头 150 至 250 字内给出结论
- 使用 H2/H3 表达具体问题，不用含糊的营销标题
- 使用列表、表格、步骤和对照，减少长篇空泛叙述
- 对关键事实给出出处、版本和日期
- 不编造数据、客户案例、资历、FAQ 或引用
- 保留作者页、GitHub、授权说明和文章更新时间
- 维护稳定的主题与更新记录，不批量删除旧文

当前 `robots.txt` 允许正常爬虫访问。若希望内容出现在 AI 搜索结果中，不要在 Cloudflare 安全设置中拦截所有 AI 搜索爬虫。`llms.txt` 不是正式排名标准，可以后续试验，但不能代替优质内容和正常搜索优化。

## 30 天执行计划

### 第 1 周

- 绑定正式域名并设置 `SITE_URL`
- 完成 Google、Bing、百度验证
- 提交站点地图
- 检查首页、关于页和文章页结构化数据
- 保存优化前的搜索表现基线

### 第 2 周

- 选出 3 篇最重要的文章
- 重写过于宽泛的标题和摘要
- 给每篇补一段开头的直接答案
- 补齐相关文章链接和一手来源
- 为确有更新的文章填写 `updatedDate`

### 第 3 周

- 发布一篇完整的项目复盘
- 发布一篇能独立解决具体问题的技术文章
- 在 GitHub README 或个人社交资料中链接正式域名

### 第 4 周

- 查看搜索平台中的抓取、索引、查询和点击
- 找出有曝光但点击率低的一页，只改标题和摘要做验证
- 记录 ChatGPT、Perplexity、Copilot 等来源的引荐访问
- 根据真实问题规划下月选题

## 每月观察指标

| 指标 | 在哪里看 | 说明 |
| --- | --- | --- |
| 有效页面数 | Google Search Console | 是否持续被索引 |
| 搜索查询与曝光 | Google、Bing、百度后台 | 用户实际用什么词找到站点 |
| 点击率与平均排名 | 搜索平台 | 判断标题摘要是否需要调整 |
| 热门页面 | Cloudflare、百度统计 | 哪些内容真正有用 |
| 外部引荐 | 统计后台 | 是否被社区、搜索或 AI 产品链接 |
| AI 引荐访问 | 统计后台来源 | 关注 `chatgpt.com`、`perplexity.ai`、`copilot.microsoft.com` 等 |
| 品牌搜索 | 搜索平台 | “知渡”“JinSun 博客”等是否形成记忆 |
| RSS 与回访 | RSS 服务、统计后台 | 是否形成稳定读者 |

建议每月固定一天记录一次，至少连续观察三个月。不要用单日波动判断 SEO 成败。

## 常见误区

- 为搜索引擎堆砌关键词，牺牲正常阅读
- 批量生成没有真实经验的内容
- 编造统计、评价、作者资历或 FAQ
- 购买低质量外链或批量交换链接
- 频繁更换域名、标题和 URL
- 所有页面使用相同标题与摘要
- 为了防爬而封禁全部 AI 和搜索爬虫
- 认为加了 `llms.txt` 就一定会被 AI 引用
- 把结构化数据当成排名保证

## 上线前检查

```powershell
npm run check
```

该命令会检查标题、摘要、canonical、robots、作者信息、JSON-LD、内部链接以及站点地图与 canonical 域名是否一致。
